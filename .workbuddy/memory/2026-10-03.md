## ProductService 秒杀方法评审（只评审未改码）

审查 `ProductService/Modules/Products/Service/ProductService.cs` 的 `Seckill`，给出分层改进方案。

现状问题（已 `dotnet build` 实测确认）：
- CS0738：`IProductService.Seckill` 声明 `Task<bool>`，实现写的是 `Task<SeckillResult>`，编译不过；
  `return await SaveChangesAsync() > 0;` 返回 bool 也转不成 SeckillResult（CS0029）。
- 读—改—写非原子，靠 RowVersion 被动报错，`catch (DbUpdateConcurrencyException)` 里返回占位
  `Message="ddd"`，吞异常且无 ErrorCode。
- `UserId` 参数未使用，无一人一单幂等；Controller 恒返回 200。
- `Program.cs` 中 `UseAuthorization()` 写在 `UseAuthentication()` 之前（顺序反了），
  且未注册 `AppExceptionFilterAttribute`（命名空间 `OutsourcingPlatform.Common`），
  业务异常会直接变 500 而非 422。

推荐方案（EF Core 9 可用 `ExecuteUpdateAsync`）：
- L1 原子扣减：`UPDATE ... SET Count = Count - 1 WHERE Id = @id AND Count > 0`，按影响行数判定
  1=成功 / 0=售罄，Repository 新增 `TryDeductStockAsync` + `ExistsAsync`。
- L2 幂等：新增秒杀订单表，(ProductId, UserId) 唯一索引。
- L3 高并发：Redis Lua 预扣库存 + RabbitMQ（docker-compose 已有 rabbitmq）异步落单。
- L4 语义：Controller 按 ErrorCode 映射 404/409，注册全局异常过滤器。

项目环境备注：net8.0 + EF Core 9.0.9，无 Redis 依赖。

## Observability / Jaeger 排查（Jaeger 里只有 jaeger-all-in-one）

环境：docker-compose 有 `jaegertracing/all-in-one`（16686/4317），productservice 通过
`Observability__OtlpEndpoint=http://jaeger:4317` 上报；VS 快速调试模式（源码挂载进容器 /app）。

已确认的事实：
- 容器 env 有 OtlpEndpoint，DNS 能解析 jaeger→172.18.0.3，Jaeger 4317 在监听。
- 容器进程 17:52 启动，而 `AddObservability` 18:06 才加进 Program.cs；18:06 之后构建
  一直被 CS0738 卡住 → **运行中的进程从未包含埋点代码**，这是 Jaeger 看不到
  ProductService 的直接原因。
- 注意：Git Bash 下 `docker exec ... /bin/...` 会被路径转换坑掉，必须 `MSYS_NO_PATHCONV=1`。
- VS 动态端口（49568/49569 等）从宿主机不可达，只有固定端口（16686/15672）可达；
  `docker restart` 会弄断 VS 的调试端口代理，需重新 F5 恢复。
